# Troubleshooting

## Setup

**The setup command says it expired.** A setup command is valid for 30 minutes and works once. Choose **New command** on the enrollment page and run the new one.

**The report expired.** After the node reports, you have 24 hours to finish on the enrollment page. Cancel the enrollment and run setup again.

**The node can't reach the panel.** Use the offline script under **The node can't reach this panel?** on the enrollment page, and paste the `nebla-enroll:v1:` line it prints. See [Connect Proxmox](/docs/proxmox#if-the-node-cant-reach-the-panel).

**Connecting fails with `fingerprint_mismatch`.** The certificate the panel sees is not one the node reported. Check that the Proxmox URL points at a node of this cluster and that no proxy sits in between. After a certificate renewal, use **Re-run setup**.

**Connecting fails with `pve_unreachable`.** The panel can't reach the Proxmox URL. Check that port 8006 is open from the machine that runs Nebla.

## OS images

**I have local storage but can't build a template.** If **Import storage** is blank when you reopen the location, check the content types on the Proxmox directory storage named `local`. Nebla rejects the selection when **Import** is missing.

1. In Proxmox, open **Datacenter → Storage → local → Edit**. Under **Content**, keep the existing selections, add **Import**, and save. If **Import** is missing from the list, check that the node runs Proxmox VE 8.4 or later.
2. In Nebla, edit the location, set **Import storage** to `local`, and save.
3. Reopen the location and confirm **Import storage** still shows `local`, then retry the template build.

**A cell says "location has no import_storage".** Built-in images need an import storage. Add `import` to a file storage's content types and pick it on the location. See [Storages](/docs/proxmox#storages).

**A cell says "no online node runs Proxmox VE 8.4 or later".** Built-in images download through Proxmox's import feature, which needs 8.4. Upgrade the nodes, or register a template you built yourself under **Your own images**.

**An image shows Failed or Partial.** Check that the nodes have outbound HTTPS to the image's download site, then choose **Retry**. Panel admins see the technical error on the admin **Activity** page.

## Servers

**"No free addresses in …"** Every address in the location's IP pools is taken. A panel admin can add a pool or widen a range.

**"This server doesn't fit in the project's quota."** Delete something, pick a smaller type, or ask a panel admin to raise the project's quota.

**"no node in this location has capacity for this server"** No enabled, online node has enough free memory, or none has the image's template.

**The console is blank.** The template probably uses a serial display. Nebla doesn't change the display type, so fix the template in Proxmox with `qm set <vmid> --vga std`.

**Resize asks you to shut the server down.** Changing a server's type needs it off. Shut it down from the Overview tab first.

**Shut down or Reboot times out.** The OS didn't respond to the ACPI request within 2 minutes. Use **Power off** or **Reset** instead.

## Volumes

**Volumes doesn't appear in the menu.** No location offers volumes yet. A panel admin must grant the token its storage permission. The location page shows the command under "Volumes need one more permission". Run it, then choose **Sync nodes**.

**"Power off the server to attach the volume."** Some servers can't take a volume while running. Power the server off and try again.

**The server stops at boot after a volume was detached.** Its `/etc/fstab` line is missing `nofail`. See [Format and mount](/docs/volumes#format-and-mount).

## Firewalls

**Rules don't take effect.** The Proxmox datacenter firewall is off. The location page warns about it. Turn it on under Datacenter > Firewall > Options.

**A server lost outbound access.** Once any of a server's firewalls has an outbound rule, only what outbound rules allow gets out. Add the outbound rules it needs, such as DNS and HTTPS.

## Sign-in

**The account page says "Passkeys need this panel on https with a domain name."** Set `PANEL_BASE_URL` to an https URL with a domain name and restart Nebla.

**Passkeys stopped working after a move.** Passkeys are tied to the host in `PANEL_BASE_URL`. Sign in with your password and add new passkeys.

**You lost your authenticator.** A panel admin can turn off two-factor login for your account from **Users**.

## Get help

- Ask in the [Nebla Discord](https://nebla.dev/discord).
- Report bugs in [GitHub issues](https://github.com/nebla-cloud/nebla/issues).
- Report security problems through [private vulnerability reporting](https://github.com/nebla-cloud/nebla/security), never in public.
