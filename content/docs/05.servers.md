# Servers

A server is a Proxmox VM that Nebla clones from an image template, with a fixed size from a server type and addresses from an IP pool. Nebla picks the node, the VM ID and the storage, so you don't have to.

## Create a server

Open **Servers** and choose **Create server**. The page has one step per choice:

1. **Location.** The Proxmox cluster or node to run on.
2. **Image.** The operating system. Images not offered in the chosen location are marked.
3. **Type.** vCPU, memory and disk.
4. **Networking.** A public IPv4 address is on by default, IPv6 is optional.
5. **SSH keys.** Keys to install for the image's default user. You can add one here.
6. **Firewalls.** Shown when the project has [firewalls](/docs/firewalls).
7. **Cloud-init.** Optional user data, up to 32 KiB, to install packages or run commands on first boot.

The summary beside the steps suggests a name, which you can change, and shows the project's quota before and after this server. If the server doesn't fit the quota, Create is blocked. Names use lowercase letters, digits and hyphens.

Nebla places the server on the online node with the most free memory that has the image, gives it a static address through cloud-init, and starts it.

The same thing from the [CLI](/docs/cli):

```sh
nebla server create --name web1 --type small-2 --image debian-13 --ssh-key laptop \
  --user-data-from-file cloud-init.yaml
```

## Overview

A server's **Overview** tab shows its status, addresses, image, type and location, live CPU, network and disk use, and its three most recent actions. You can rename the server and edit its labels here. Labels are `key=value` pairs that [firewalls](/docs/firewalls) and filters select on.

## Power

| Button | What it does |
| --- | --- |
| Power on | Starts the server. |
| Shut down | Asks the OS to shut down cleanly. |
| Reboot | Asks the OS to restart cleanly. |
| Power off | Stops the server straight away, like pulling the plug. |
| Reset | Restarts the server straight away. |

Power off and Reset sit under the menu on a running server. A power action that hasn't finished after 2 minutes fails as timed out.

Images built from the built-in catalog don't ship the QEMU guest agent. Shut down and Reboot use ACPI, and graphs work without it.

## Console

The **Console** tab opens the server's screen in the browser. It has buttons for Ctrl+Alt+Del, pasting text and full screen, and **Pop out** opens it in its own window. Nebla proxies the connection, so you never need Proxmox credentials or network access to the host.

- The server must be running.
- One console session runs at a time.
- A session closes after 30 minutes idle, or after 8 hours.
- Paste types US-keyboard ASCII only.

## Graphs

The **Graphs** tab shows CPU, disk read and write, and network in and out, over the last hour, day, week or month. The hour view refreshes every minute.

## Rebuild

**Rebuild** erases the server's disk and reinstalls it from the image you pick. The server keeps its name, addresses and attached volumes. A running server starts again afterwards.

## Resize

**Resize** changes the server type. Shut the server down first. Tick **Grow the disk too** to give it the new type's disk size. Without it, the disk keeps its current size, so you can try a bigger type and move back later. Disks never shrink.

## Delete

Delete is on the Overview tab, and you confirm it by typing the server's name. Nebla deletes the VM and frees its addresses. Attached [volumes](/docs/volumes) are detached and kept.

## Activity

Every change runs as an [action](/docs/api#actions) with a status and progress. The server's **Activity** tab lists its actions, and the project's **Activity** page lists them all, filtered by running or failed. A failed action shows a plain message. Panel admins also see the technical detail.

While an action runs on a server, a second change to the same server is refused as locked until the first one finishes.
