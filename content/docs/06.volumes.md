# Volumes

A volume is extra disk space you attach to a server. It keeps its data when you detach it, rebuild the server or delete the server, and you can attach it to another server in the same location later. Volumes count against the project's quota.

Manage volumes on the **Volumes** page, on a server's **Volumes** tab, with the [CLI](/docs/cli) (`nebla volume …`) or the [API](/docs/api). If Volumes doesn't appear, no location in the panel offers volumes yet. A panel admin sets that up per location (see [Connect Proxmox](/docs/proxmox#storages)).

## Create a volume

Choose **Create volume** and give it a name, a size from 10 to 10240 GB, and a location. You can attach it to a server in the same location straight away.

```sh
nebla volume create --name data --size 50 --server web1
```

Some rules:

- A volume and its server must be in the same location. In some locations a volume also stays on one host, so it attaches only to servers on that host. The panel greys out servers it can't attach to and says why.
- A server holds at most 14 volumes.
- Some servers can't take a volume while running. If attaching fails with "Power off the server to attach the volume.", power it off and try again.

## Find the disk

Linux names disks like `/dev/vdb` in the order they were attached, so the name can change after a detach, a reboot or a rebuild. Use the stable path instead. The panel shows it on the volume and on the server's Volumes tab:

```sh
/dev/disk/by-id/virtio-nb-vol-<id>
```

To list the volumes a server can see:

```sh
ls -l /dev/disk/by-id/ | grep nb-vol
```

## Format and mount

A new volume is empty. Make a filesystem on it once. This erases whatever is on the volume:

```sh
sudo mkfs.ext4 -L data /dev/disk/by-id/virtio-nb-vol-42
sudo mkdir -p /mnt/data
sudo mount /dev/disk/by-id/virtio-nb-vol-42 /mnt/data
```

For XFS, use `sudo mkfs.xfs -L data` instead.

To mount it at every boot, add a line to `/etc/fstab` that uses the label, not `/dev/vdX`:

```ini
LABEL=data  /mnt/data  ext4  defaults,nofail  0  2
```

Keep `nofail`. Without it the server stops at boot when the volume is detached. Check the line with `sudo mount -a` before you reboot.

## Make it bigger

Volumes only grow, up to 10240 GB. Resize in the panel or with:

```sh
nebla volume resize data --size 100
```

An attached volume shows its new size on the server within a few seconds. A detached volume gets its new size when you next attach it. Then grow the filesystem, which works while it's mounted:

```sh
sudo resize2fs /dev/disk/by-id/virtio-nb-vol-42   # ext4
sudo xfs_growfs /mnt/data                          # XFS takes the mount point
```

## Detach, move and delete

Stop anything using the volume and unmount it first, or data still in memory can be lost:

```sh
sudo umount /mnt/data
nebla volume detach data
nebla volume attach data --server web2
```

To delete a volume, detach it first. Deleting erases its data for good.

When you delete a server, its volumes are detached and kept. When you rebuild a server, its volumes stay attached.

The [volumes guide](https://github.com/nebla-cloud/nebla/blob/main/docs/volumes.md) in the repository has more detail, and the [Proxmox setup reference](https://github.com/nebla-cloud/nebla/blob/main/docs/proxmox-setup.md#9-volumes) explains how volumes look on the Proxmox side.
