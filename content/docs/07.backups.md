# Backups

A backup is a copy of a server's boot disk, stored on a Proxmox Backup Server away from the host the server runs on. Turn backups on and Nebla backs the server up once a day and keeps the last few. You can also back up on demand. If something goes wrong, you can roll the server back to any of them.

Manage backups on a server's **Backups** tab, with the [CLI](/docs/cli) (`nebla server backup …`) or the [API](/docs/api). If the tab says "Backups are turned off for this location", a panel admin hasn't set up backup storage there yet (see [Connect Proxmox](/docs/proxmox#backups)).

## What a backup covers

- The boot disk only. [Volumes](/docs/volumes) aren't included, so back up their data yourself.
- Restoring puts the boot disk back as it was. Anything written to it since the backup is lost.

## Turn backups on

On the server's **Backups** tab, switch on **Daily backups** and choose how many to **Keep**, from 1 to 14. The default is 7. The tab shows the next and last backup times in your timezone. You can also tick **Enable daily backups** when you create a server.

```sh
nebla server create --name web1 --type small-2 --image debian-13 --ssh-key laptop --backups --backup-keep 5
nebla server backup enable web1 --keep 7
nebla server backup disable web1
```

Turning backups off keeps the backups you already have. You can still restore and delete them one at a time.

## Back up now

**Back up now** makes a backup right away, or as soon as the host is free. It's there while daily backups are on.

```sh
nebla server backup now web1
```

Scheduled backups and backups you start yourself share one pool. After each successful backup, Nebla deletes the oldest ones beyond your Keep number.

## When backups run

A panel admin sets a backup window for each location, in UTC. Nebla spreads servers across the window, so each server has its own start time, and backs each one up once a day.

Only one backup runs on a host at a time, so a backup can start a little after its time and still count for that day. A backup that is queued shows as **Waiting for its turn** and doesn't lock the server. While a backup is actually running, other changes to the server are refused. Try again when it finishes.

## Restore

Choose **Restore** on a backup, then type the server's name to confirm. Nebla doesn't take another backup first, so choose **Back up now** first if you might want the current disk back.

```sh
nebla server backup list web1
nebla server backup restore web1 42
```

The server keeps its addresses, type, attached volumes and firewalls as they are now. Volumes stay attached and untouched. Only the boot disk goes back.

If the server's network hasn't changed since the backup, it comes back as it was, with the same SSH host keys. If it has changed, the server is set up as new: its network is configured again, its SSH host keys change and its cloud-init user data runs again. The restore dialog and the CLI tell you before you confirm.

While a restore runs, other changes to the server are refused.

### After a rebuild

A [rebuild](/docs/servers#rebuild) replaces the operating system, but backups taken before it stay. Restoring one of those brings back the old operating system. The image the panel shows for the server doesn't change when you restore, so it can name an image the disk no longer runs.

## Delete backups

```sh
nebla server backup delete web1 42
```

Deleting a backup is permanent. You can't delete a backup while it's being restored.

When you delete a server, its backups are deleted too. The delete dialog tells you how many.

## Quota

Backups count against the project's quota (`max_backups`). A server with backups on reserves its whole Keep number, whether or not those backups exist yet. A server with backups off counts the backups it still has. Turning backups on, or raising Keep, fails when the total would go over the project's limit. Because the room is reserved up front, a daily backup never fails for quota.

Projects that non-admin users create start with a limit of 35 backups. A panel admin can change it.

## Backups and snapshots

Snapshots are a separate feature. They differ from backups like this:

| | Backup | Snapshot |
| --- | --- | --- |
| What | A copy of the boot disk, kept away from the host | A saved boot disk you can build new servers from |
| Made | Daily, or when you choose Back up now | When you ask |
| Used for | Rolling this server back in place | Making new servers |
| Lifetime | Rotates, keeping the last few. Deleted with the server | Kept until you delete it, even after the server is gone |

The [backups guide](https://github.com/nebla-cloud/nebla/blob/main/docs/backups.md) in the repository has more detail.
